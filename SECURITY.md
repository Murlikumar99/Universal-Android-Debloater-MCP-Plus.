# Security Policy & Threat Model (`SECURITY.md`)

## 1. Core Security Principles
- **Zero Shell Interpolation**: All ADB invocations use `child_process.execFile` with explicit argument arrays (`shell: false`). Package names are validated against `^[a-zA-Z][a-zA-Z0-9_]*(\.[a-zA-Z0-9_]+)+$` and device serials against `^[a-zA-Z0-9][a-zA-Z0-9._:-]{0,63}$`.
- **Exhaustive Mutating Command Allowlist**: `src/debloat/executor.ts` rejects any command outside the five allowlisted `--user 0` package templates.
- **Unbypassable Out-of-Band Human Approval**: AI clients cannot call an MCP tool to issue an approval token. Tokens must be generated by a human via the local CLI (`npx tsx src/index.ts approve <plan-id>`) or the authenticated human approval terminal, are bound to the plan SHA-256 hash and device fingerprint, expire after 10 minutes, and are single-use.
- **Server-Side API Security**: The web console backend enforces `HttpOnly` signed session cookies, strict CORS origin allowlisting (never `*`), Origin/Referer validation, per-IP and per-session rate limiting (`429` with `Retry-After`), and redacted structured logging.

## 2. Reporting a Vulnerability
Please report security vulnerabilities privately via GitHub Security Advisories rather than public issues. Include reproduction steps and the affected module (`executor.ts`, `approval.ts`, `safetyEngine.ts`, or `server.ts`).
